# 디자인 규칙

- WantedSans를 기본 글꼴로 사용한다. 본문과 데이터는 읽기 쉬운 크기를 우선하며,
  작아서 정보를 읽을 수 없는 UI를 만들지 않는다.
- 전체 앱은 밀도 높은 다크 DFIR 작업 화면이다. 불필요한 설명글, 장식, 의미 없는
  요약 통계, 과도한 여백을 제거하고 정보의 정렬과 계층으로 구분한다.
- Neumorphism은 외부 표면의 한 단계만 사용한다. 카드 안 카드 등 2단계 이상의
  중첩 그림자/부조 효과를 만들지 않는다.
- 모서리 반경, 버튼 높이, 탭·칩 크기, 글꼴 크기, 여백을 뷰 간에 통일한다. 같은
  데이터/아티팩트의 상세 보기는 어디서 열어도 같은 정보 구조와 라벨을 제공한다.
- 목록·상세 페이지네이션은 **모든 뷰에서 10건 고정**이다. 카드 안에 원본 레코드를
  펼쳐 보여 주는 경우도 같은 10건을 쓴다. 뷰마다 다른 페이지 크기를 쓰지 않는다.
- 사이드바에서 "데이터 없음"으로 표시되는 항목은 **선택할 수 없다**. 원본 파일이
  없어서 비어 있든 파싱 결과가 0건이든 동작이 같아야 한다 — 항목은 목록에 남겨
  파서가 돌았다는 사실을 보여 주되, 클릭·호버·선택 강조를 주지 않는다
  (2026-09-03 사용자 확정. 0건 항목을 열어 빈 화면을 확인하는 용도는 폐기).
- 분석가용 탐색·탭·뷰 라벨은 기본적으로 한글로 표기한다. 단, 원본 증거 값으로
  보존해야 하는 아티팩트명·필드 식별자는 임의 번역하지 않는다.
- 색상은 의미를 갖는다. 위험·오류는 빨강, 경고는 노랑, 선택/탐색은 파랑으로만
  사용한다. 아티팩트 식별 색상은 위험도를 뜻하지 않으며, 진한 외곽선과 낮은 채도의
  내부 배경으로 표시한다.
- 타임라인·필터의 아티팩트 칩은 동일한 색상 체계와 고정 폭을 쓴다. EventLog의 여러
  원본 로그(Security/System/Application 등)는 화면·필터에서 모두 `EventLog` 하나로
  표기하고 한 번에 제어한다.
- 북마크는 별표 아이콘이 아니라 해당 행의 배경/좌측 강조로 구분한다.
  **확정 예외:** 분석 정보(북마크 전용) 뷰는 모든 행이 북마크이므로 배경 강조를
  하지 않는다 — 구분 정보를 주지 못하기 때문이다. 행 왼쪽의 북마크 아이콘
  타일은 유지한다 (2026-09-03 사용자 확정).
- 로딩 상태는 정적인 문구만 두지 않는다. 회전형 로딩 표시, 진행 바의 지속 애니메이션,
  진행 중임을 보여 주는 점 애니메이션을 제공한다. 파싱 완료 뒤 실패 아티팩트는 진행
  바 자리에 명확히 표시한다.
